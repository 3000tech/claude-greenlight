<objective>
Turn the tracer's minimal state-file reader into the real engine: it must derive a verdict
for every visible session from `monitor-state/` alone, survive every shape of broken file,
recover a session whose turn died without emitting any hook event, tell a paused container
apart from a dead one, and keep sessions from hookless containers visible.

Purpose: this is the half of the phase that decides whether the state-file engine is
trustworthy enough to become the default in Phase 3. Everything the hybrid verdict listed
as hook-silent — Esc interrupt, permission denial, container kill, abandoned prompt, old
images without hooks — is covered here or it is not covered at all.

Output: `scan_state_files()` complete, container liveness in `scan_containers()`, and the
test classes that pin all of it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Shared `~/.claude/monitor-state/` → monitor process | Files written by containers are parsed by the Windows-side monitor; any container can write any filename into this directory |
| Monitor process → `docker` CLI | A subprocess invocation whose output is parsed and whose failure must never stop the tick |
| Monitor engine → the user's state files | The engine now deletes files under a pruning policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Denial of Service | `scan_state_files` parsing attacker-shaped or half-written JSON | high | mitigate | Every read is wrapped in `try/except (OSError, json.JSONDecodeError)`, every field access is defaulted, and a failed record drops one session rather than the tick; nine broken-shape cases are asserted in `Goal10_StateFileRobustness` |
| T-02-13 | Tampering (data loss) | The engine's pruning sweep unlinking live state files | high | mitigate | Pruning is bounded to files older than `STATE_PRUNE_AGE_SEC` (24h), which is 24 times the one-hour visibility window, wrapped in `try/except OSError`, and asserted by a test that a fresh file survives a prune pass |
| T-02-14 | Spoofing | A container writing a state file whose `hostname` claims another container's identity | medium | accept | The shared mount already grants every container write access to every other container's lock files and jsonl directories; the state directory introduces no new privilege, and the only consequence is a wrong label in a non-rendered shadow list. Revisit if the mount's trust model changes |
| T-02-15 | Denial of Service | A hung or slow `docker inspect` blocking the tick | medium | mitigate | The call keeps its existing 2-second timeout and `try/except (OSError, subprocess.TimeoutExpired)`; no second subprocess call is added, the existing one is extended |
| T-02-16 | Tampering | Path traversal through a filename in `monitor-state/` | medium | mitigate | Only the filename stem is used as a session id for lookup — it is never re-joined into a new path — and the glob is confined to `STATE_DIR`; the writer-side guard in plan 02-01 stops such a name being created in the first place |
| T-02-SC | Tampering | npm/pip/cargo installs | high | accept | Zero new external packages this phase (RESEARCH.md Package Legitimacy Audit: not applicable); no install task exists to gate |
</threat_model>
