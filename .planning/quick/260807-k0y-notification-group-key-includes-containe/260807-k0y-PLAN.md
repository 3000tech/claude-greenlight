<objective>
Put container identity into the notification group key so two containers of the same project (nursy and nursy-2) get separate notification channels instead of one shared, mutually-silencing channel.

Purpose: quick-260807-iz2 keyed work groups on `project label :: normalized root`. Every devcontainer of the same project mounts at the same path and carries the same label, so two containers the user runs as INDEPENDENT jobs collapse into one group — nursy-2 finishing a turn is silenced while nursy is still working, which is exactly the notification the user needs. The monitor UI already disambiguates these containers per-container via hostname (derive_alias_key, session_display_name); the group key is the one identity consumer that does not.

Output: a three-part group key (label :: worktree-folded root :: hostname), its rewritten rationale, the regression that pins the nursy/nursy-2 split, and the re-fixtured suites.

Accepted consequence — a locked user decision, NOT to be re-litigated or worked around: the cross-container merge of the real 2026-08-07 case (main tree on host 8d5f9694f1de + worktree prd-gsd on host 4353e1441213) disappears; those two sessions become separate groups. Both real episodes stay suppressed anyway, because `background_tasks_count` was 1 in both Stops and that condition is checked first.
</objective>
