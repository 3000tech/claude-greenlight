<objective>
Make the shape of a `background_tasks` descriptor observable from hook payloads — field names and enum-like values only, never command text — then record in TEST-MATRIX what the live samples show about telling a background AGENT apart from a background SHELL at turn end.

Purpose: at 13:15 local on 2026-08-17 the monitor paged the user for session 34518633 (yunoai, cwd /workspace/cloudrun-jobs) after a Stop at 11:14:15Z with `background_tasks_count: 2`. Both background tasks were gsd-planner agents running in background; the session re-invoked itself ~40s later and went back to working. The user never needed to intervene. D-03 / case 17 rev.2 is deliberate and correct for a plain bg shell — a build or a test running is not proof Claude owes the user a reply — but a background AGENT is different in kind: its completion re-invokes the session, so the turn is guaranteed to continue. If, and only if, the hook payload distinguishes the two, the rule can be refined instead of reversed.

Nobody currently knows whether it does. `~/.claude/hook-events.log` records only the payload's top-level `keys` plus the LENGTH of `background_tasks` — never the entries themselves, by the Phase 1 privacy discipline. This task closes exactly that gap, at the narrowest possible width.

Output: a name-and-enum-only descriptor sampler in the diagnostic logger (deployed live, so sampling starts immediately), a repeatable privacy-safe report over the log, and a rev.3 entry in TEST-MATRIX section 4.

Scope boundary — hold this line: `hooks/state-writer.sh` is NOT touched. This task produces evidence and a documented decision. The verdict change (Stop with only-agent background tasks maps to working) is a FOLLOW-UP quick task, opened only if the samples make the discrimination unambiguous. D-03 stands for shells either way.

```jq
background_tasks_shape: (
  if (.background_tasks | type) == "array" then
    [ .background_tasks[0:5][]
      | (if type == "object" then . else {} end)
      | {keys: keys}
        + with_entries(select(
            (.key | IN("id","task_id","agent_id","shell_id","type","kind","task_type","agent_type","subagent_type","status","state","source","mode","tool_name"))
            and (
              ((.value | type) == "boolean")
              or ((.value | type) == "number")
              or (((.value | type) == "string") and (.value | test("^[A-Za-z0-9_.:-]{1,64}$")))
            )
          ))
    ]
  else null end
)
```
