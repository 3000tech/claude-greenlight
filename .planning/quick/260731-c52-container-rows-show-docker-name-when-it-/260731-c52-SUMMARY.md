# Quick Task 260731-c52: Docker Rows Show Container Name Summary

**Pure `container_display_name()` helper makes duplicate-project docker rows distinguishable (`dev-tools` / `dev-tools-2`) while keeping the project label as the sole identifier for sorting, filtering, and container-to-session mapping.**

## Performance

- **Duration:** 6 min
- **Tasks:** 2 completed
- **Files modified:** 2 (monitor.py, test_monitor.py)

## Accomplishments
- Added module-level `container_display_name(c: dict) -> str` next to `scan_containers()`: when the docker name carries the project label as a prefix, the name is displayed (disambiguating launcher duplicates like `dev-tools-2`); otherwise the project label is displayed, preserving today's behaviour for pre-existing containers with docker-generated names
- Wired the helper into the single container render loop call site (monitor.py ~2098), leaving row keying (`key = c["name"]`), the container sort, and all label maps untouched
- Added `Goal18_ContainerDisplayName` with 7 unit tests: the three core behaviours (suffixed duplicate, exact match, random-name fallback) plus four edge guards (empty/missing name, shared-but-shorter head, dict-mutation purity, same-project-pair distinct-text/shared-identity)

## Task Commits

2. **Task 2: Lock the fallback edges and prove the change is display-only** - `ebb25b0` (test)

_Note: task types were `tracer`+`tdd` (Task 1, one commit since tests and implementation were authored together and verified before commit) and `auto` (Task 2)._

## Files Created/Modified
- `monitor.py` - Added `container_display_name()` helper (module level, before `scan_containers()`); render loop resolves `display` once and configures the project Label from it instead of `c["project"]` directly
- `test_monitor.py` - Added `Goal18_ContainerDisplayName` (7 tests) as the new final section before the `unittest.main()` footer

## Decisions Made
- The prefix test (`name.startswith(project)`) is the entire disambiguation rule — it anchors the displayed name to the row's own project label, so a crafted or random docker name can never make a row display a different project's identity (also recorded in the plan's threat register as T-quick-c52-01, mitigated)
- Defensive field reads (non-string/missing `name` or `project` degrade to the project label, or empty string if project itself is missing) — the render loop runs on the tk timer with no error boundary above it, so a malformed row must never raise
