<objective>
Finish shadow mode: make every divergence record carry enough context to settle which
engine was right, keep the log small enough to actually read after a week of real usage,
and give `monitor.py` the `--state-files` mode that renders the new engine directly for
hands-on verification — while the default invocation stays byte-identical to today.

Purpose: the divergence log is the entire evidence base for the Phase 3 flip decision. If
a record does not say what the legacy engine was looking at when it disagreed, the review
conversation degenerates into re-reading jsonl by hand, which is exactly what this refactor
exists to stop.

Output: complete divergence records with episode tracking and a size guard, plus the
`--state-files` diagnostic mode.
</objective>

  <action>
Bring the divergence record up to the standard D-04 sets, then stop it from drowning the
reviewer.

First, surface the legacy evidence. In `scan()`, add `auq_locked` and `working_locked` to
the session dict it appends — both booleans are already computed a few lines above and
simply not reported. This is strictly additive: the rendering path reads named keys and is
unaffected, and the existing tests assert on specific keys rather than on the dict's exact
shape.

Then widen `diff_verdicts(legacy, shadow, tick)`. Compare over the UNION of keys, not the
intersection: a session one engine sees and the other does not is one of the most
informative divergences there is (a paused container the shadow engine keeps and legacy
drops, or a brand-new session one engine picks up a tick earlier). Represent the missing
side's verdict as `ABSENT`. For every differing key emit a record carrying `ts`, `ts_ms`,
`tick`, `key`, `session_id`, `name`, `legacy_verdict`, `state_file_verdict`, plus the
state-file context `state`, `last_event`, `hostname`, `background_tasks_count` and
`age_sec`, plus `legacy_evidence`: a single compact string assembled from the legacy dict's
`action` label, its `working_locked` and `auq_locked` booleans, its `bg`, `monitors` and
`agents` counts, and its age. That is precisely the set a reviewer needs to say "legacy was
pinned working by a lock that should have cleared" or "the hook engine saw the modal six
seconds earlier" without opening a jsonl. Return the records sorted by `key`.

Emit no field that judges the disagreement. No `likely_cause`, no `winner`, no severity —
D-04 puts classification in the review conversation, and a field that pre-judges it would
quietly steer the decision this whole phase exists to inform.

Next, add episode tracking so a steady disagreement is one line, not one line every five
seconds. Write it as a pure function — `filter_divergence_events(records, prev, tick)`
taking the current tick's records and the previous tick's per-key state, returning the
events to write and the next state. A key whose verdict pair is new, or whose pair changed,
yields a `diverged` event. A key that was diverging and is not in this tick's records
yields a `resolved` event carrying `since_ts_ms` and the `ticks` the episode lasted. Keep
it pure so it is testable without constructing a tkinter app; hold the state dict on
`MonitorApp` and pass it through in `refresh()`.

Finally, guard the log's size in `write_divergences`. Add
`DIVERGENCE_LOG_MAX_BYTES = 5 * 1024 * 1024` next to `DIVERGENCE_LOG`, mirroring the
threshold `event-logger.sh` already uses for the same shared mount. Before appending, stat
the file; if it is over the threshold, truncate it and write a marker record noting that
truncation happened, so a reader can never mistake a truncation for a gap in observation.
No flock is needed here and none should be added: the monitor holds a process-wide
singleton lock, so this log has exactly one writer, unlike `hook-events.log` which every
container appends to. Wrap the whole write in `try/except OSError: pass` — a full disk or a
transient mount hiccup must cost a log line, never a tick.

In `test_monitor.py`, add `Goal14_DivergenceRecords`: agreement yields zero records; a
status disagreement yields one record carrying both verdicts, the state-file context and a
non-empty `legacy_evidence`; a key only in the legacy list yields `state_file_verdict` of
`ABSENT` and a key only in the shadow list yields `legacy_verdict` of `ABSENT`; two empty
lists yield zero records; and records from a multi-session tick come back sorted by key.
Add `Goal15_DivergenceEpisodes`: the same disagreement across three consecutive ticks
writes one `diverged` event; a change of verdict pair mid-episode writes a second
`diverged`; a return to agreement writes one `resolved` carrying a `ticks` value greater
than one; and a session disappearing while diverging also resolves. Add
`Goal16_DivergenceLogGuard`: a log already over `DIVERGENCE_LOG_MAX_BYTES` is truncated and
carries a marker before the new line; a write to an unwritable path raises nothing and
returns normally; and no `legacy_evidence` string contains the raw prompt or tool-input text
seeded into the fixture jsonl. Point `monitor.DIVERGENCE_LOG` at a TemporaryDirectory in
every one of these tests.
