<objective>
Prove the whole Phase 2 architecture end-to-end on one path: a `Stop` hook event inside a
container becomes an atomically-written per-session state file on the shared mount, the
Windows-side monitor derives a WAITING verdict from that file without touching any jsonl,
and a disagreement with the legacy verdict is recorded in a divergence log — while the
overlay keeps rendering the legacy verdict exclusively.

Purpose: every later plan in this phase widens this path (more events, staleness, docker
liveness, hookless fallback, richer divergence records). If the atomic write, the
cross-mount read, or the dual-engine comparison is wrong, it is wrong here, after one
commit, instead of after five.

Output: `hooks/state-writer.sh`, `hooks/state-writer-events.json`, state-writer
registration in `hooks/install.sh`, the state-file engine seam in `monitor.py`, and
`test_state_writer.py`.
</objective>

<assumption_delta_decision>
**Noun that is now primary:** the session-state verdict source.

**Decision: `add-alongside`.** Phase 2 deliberately introduces a second verdict source
(the state-file engine) next to legacy jsonl parsing rather than promoting it. The
promote happens in Phase 3, gated on shadow-mode divergence evidence (D-03).

**Accepted debt:** two engines derive the same verdict every tick; a behavioural change
must be made twice or it shows up as divergence noise. `monitor.py` grows before it
shrinks.

**What forces the later promote:** a review window (~1 week of real usage, D-03) with no
unexplained divergences. If divergence review instead shows the state-file engine is
systematically right where legacy is wrong, that accelerates the promote; if hooks prove
unreliable on the user's Claude Code version, the add-alongside stays and Phase 3 is
rescoped.

**Invariant test encoding the intent:** `select_render_sessions(legacy, shadow, False)`
returns the legacy list *object*, asserted by identity — the structural guarantee that
"second source exists" never silently becomes "second source renders".
</assumption_delta_decision>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Claude Code → hook script stdin | Untrusted-shaped JSON payload crosses into a script that builds a filesystem path from one of its fields |
| Container → shared `~/.claude` 9p mount | Files written inside a container become readable by the Windows host process and by every other container |
| Hook script → Claude Code control flow | `PermissionRequest`, `PostToolBatch` and `Stop` interpret a non-zero exit or a decision JSON on stdout as a directive |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | `state-writer.sh` path construction from `session_id` | high | mitigate | Reject any `session_id` not matching `^[A-Za-z0-9._-]+$` with exit 0 before it is used in a path; covered by a test feeding a session_id containing a path separator |
| T-02-02 | Tampering / Denial of Service | `state-writer.sh` exit code and stdout on blocking-capable events | high | mitigate | Every code path ends in `exit 0` and nothing is written to stdout; test asserts empty stdout and exit 0 for empty, non-JSON, `{}` and field-missing payloads |
| T-02-03 | Information Disclosure | State-file contents on the shared mount | high | mitigate | Only scalar verdict fields are emitted (`state`, `ts`, `ts_ms`, `cwd`, `hostname`, `last_event`, `background_tasks_count`); `tool_input`, `tool_response`, `prompt`, `message` and background-task descriptors are never read into the record |
| T-02-04 | Tampering (data loss) | Mid-write kill leaving a truncated state file | high | mitigate | Same-directory temp file plus `mv -f`; never a direct redirect onto the final path; proven by the SIGKILL loop in Task 2 |
| T-02-05 | Tampering | `install.sh` corrupting the user's live `settings.json` | medium | mitigate | Reuse the existing backup-then-`python3 -c json.load`-validate-then-`mv` sequence; the state-writer pass is separate from the lock merge so lock behaviour stays byte-identical |
| T-02-06 | Denial of Service | Monitor crash on a malformed or partially-written state file | medium | mitigate | `_read_state_file` catches `OSError` and `json.JSONDecodeError` and guards `isinstance(obj, dict)`; a failed read drops one session, never the tick |
| T-02-SC | Tampering | npm/pip/cargo installs | high | accept | Zero new external packages this phase (RESEARCH.md Package Legitimacy Audit: not applicable); no install task exists to gate, so there is no supply-chain surface to check |
</threat_model>
