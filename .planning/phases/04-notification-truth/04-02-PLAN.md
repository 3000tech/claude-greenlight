<objective>
Put the origin host on every notification, on every channel, from one build site.

CONTEXT.md decision 3 is cited here as **D-03**: title format `Claude ready — {label} @ {host}`
for ALL notifications, local and remote alike (`nursy @ macbook-devbox`,
`claude-greenlight @ matteo`), built in `notification_text()` (monitor.py:1445) and nowhere else.

Purpose: NOTIF-03, plus the phase's live verification vehicle. Today a title is
`Claude ready — nursy` and the user cannot tell which machine is asking — a question that does
not exist yet on a single PC and becomes unanswerable the moment Phase 5 lands devbox sessions in
the same overlay. Doing it now, uniformly, means Phase 5 inherits a title that is already correct
rather than having to retrofit one.

Scope discipline for the host source: for this phase every state file in
`~/.claude/monitor-state/` was written on THIS machine — the `hostname` field holds a container
id, and every one of those containers runs here. So the resolution is "this machine's friendly
name", with one explicit seam (`origin_host` on the session dict) for Phase 5 to plug remote
hosts into. Do not build a remote host map, a hostname→machine table, or a transport. That is
Phase 5's design discussion and it is deliberately undecided.

Output: the host-aware notification path, the README text describing it, and the 04-UAT.md
runbook that carries the phase's fourth success criterion — the overnight live run — including
the devbox update procedure it depends on.
</objective>
