<objective>
Stop `idle_prompt` Notification events from masquerading as "the user is needed", and stop
them from leaking a held notification through the background-tasks gate.

CONTEXT.md numbers its locked decisions 1/2/3; this plan cites them as **D-01** (idle_prompt is
ignored outright) and **D-02** (a held notification releases only when background work truly
ends). Both are locked — do not revisit, do not soften, do not "heartbeat" the idle ping.

Purpose: NOTIF-01 and NOTIF-02. The overnight devbox log of 2026-08-19 was 45/45 `idle_prompt`
Notifications and roughly 20 pushes to a self-resuming loop session that never needed a human.
This machine's own logs carry the same signature: 31 `idle_prompt` vs 2 `permission_prompt`
events in `~/.claude/hook-events.log`, and 10 `notifications.log` records with
`outcome: sent`, `reason: gate_cleared`, `type: needs_input` — the gate leak, ten times.

Mechanism, verified from the live payload key set: a real `Notification` payload carries exactly
`cwd, hook_event_name, message, notification_type, prompt_id, session_id, transcript_path`
and **no `background_tasks` key**. So an idle ping did two things at once — flipped the record to
`needs_input`, and rewrote `background_tasks_count` to 0, which is precisely the condition
`gate_notification()` reads to release a hold opened on in-flight background work. One fix at the
writer closes both: an ignored event writes nothing, so the last real record (waiting,
`background_tasks_count` 1) stands untouched and the hold stands with it.

Rejected alternative, recorded so it is not "improved" later: registering the hook with a
`permission_prompt` matcher in `state-writer-events.json` instead of guarding inside the script.
Rejected because it fails toward silence — any future notification_type would stop writing
`needs_input` at all. The in-script guard fails toward notifying: only the exact literal
`idle_prompt` is ignored, everything else keeps today's behaviour.

Output: the writer guard, an end-to-end regression suite replaying the real episodes, and the
TEST-MATRIX rows that record the changed verdict.
</objective>

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-01 | Information disclosure | state-writer.sh Notification branch | medium | mitigate | Read `notification_type` (a short fixed enum) only; never read, capture or log the sibling `message` field, which 01-REVIEW.md flagged as content-bearing. | T-04-04 | Tampering | dependency supply chain | low | accept | No package-manager install of any kind in this plan (no npm/pip/cargo); Python standard library and `jq` only, both already present. |
