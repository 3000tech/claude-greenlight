<decisions_made>

Phase 5 design (locked, full rationale and rejected alternatives in `05-CONTEXT.md`):
- **Peer-to-peer, not hub-and-spoke**: every machine optionally runs the same read-only endpoint
  exposing its own state, plus a config list of peers it wants to see. Chosen over a PC-centred
  hub because the user's always-on machine is the devbox — a hub on the PC leaves the phone panel
  dead whenever the PC is off.
- **Private network only**: binds the Tailscale address by default, read-only, state-only (never
  transcript content). LAN fallback documented honestly. No external hosting, ever.
- **Plug-and-play preserved** (the user's OSS concern, treated as a first-class constraint): a
  single-machine user changes nothing; enabling remote costs two gestures; the monitor core never
  learns networking.
- **Notification ownership**: visual channels from the panel you are looking at; Telegram only
  from the session's home machine. Resolves OPS-01 in advance — the devbox instance stays.

Process: development happens on `feat/*` branches, `main` is merge-only
(`git.branching_strategy: phase` in config).

Phase 4 semantics: `idle_prompt` is ignored outright — no state, no colour, no notification —
and the fail-safe direction is deliberate: only the exact literal `idle_prompt` is ignored, so an
unknown or missing `notification_type` still pages. The system fails toward paging, never silence.
</decisions_made>

## Notes for whoever plans Phase 5

- `05-RESEARCH.md`'s load-bearing finding: `monitor.py` imports tkinter unconditionally at module
  level, so a standalone headless endpoint script cannot `import monitor`. The tkinter-free state
  logic has to be extracted into a shared module **first** — that refactor is Phase 5's opening
  move, and it is exactly what `05-CONTEXT.md`'s "the monitor core must not learn networking"
  already implies.
- The endpoint must return computed state, not raw state files: part of the staleness-pinning
  evidence is jsonl-derived and must not leave its machine under the state-only rule. Each machine
  computes its own `age_sec` too, so clock skew between machines cannot distort staleness.
- Unverifiable from this Linux container and flagged as such in the research: whether Windows
  raises a firewall prompt when the endpoint binds. Test it live on the PC before the README
  promises anything about configuration-free setup.
